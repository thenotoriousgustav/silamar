## 🎯 Project Overview

**App Name:** SiLamar
**Tagline:** Lamar Kerja Lebih Cerdas
**Target Users:** Fresh graduates in Indonesia (21-25 years old)
**Business Model:** Freemium (Free tier + Credit pack + Pro subscription)
**Payment Gateway:** Midtrans (one-time credit purchase + recurring subscription)

---

## 🧩 Features

### Free Tier (No login required to try, login required to save)
- Resume/CV Builder (ATS-friendly templates, PDF export)
- Job Application Tracker (Kanban board and table: Dilamar, Interview, Penawaran, Ditolak)

### Paid Features (Credit or Pro subscription)
- AI Resume Analyzer (ATS score, improvement suggestions)
- AI Resume Analyzer vs Job Description (match score + keyword gap)
- AI Cover Letter Generator
- Skill Gap Analysis (compare user skills vs job requirements)
- Mock Interview AI (question generation + answer feedback)

### Credit System
- New user gets 3 free credits on signup
- 1 credit = 1 AI feature usage
- Credit packs: starter (5 credits Rp15.000), standard (15 credits Rp35.000), pro (30 credits Rp60.000)
- Pro subscription: Rp99.000/month = unlimited AI features

---

## 🛠 Tech Stack

- **Framework:** Next.js 16 (App Router, Server Components, Server Actions)
- **Language:** TypeScript (strict mode)
- **Styling:** Tailwind CSS v4
- **UI Components:** shadcn/ui
- **ORM:** Drizzle ORM
- **Database:** PostgreSQL via Neon DB (serverless)
- **Authentication:** Better Auth (email/password + Google OAuth)
- **File Storage:** Cloudflare R2 (S3-compatible, for resume PDF uploads)
- **AI:** Google Gemini 2.0 Flash API with vercel ai sdk library
- **Payment:** Midtrans (credit card, GoPay, QRIS, Virtual Account)
- **Email:** Resend (transactional email)
- **Deployment:** Vercel
- **Package Manager:** pnpm

## 🗄 Database Schema (Drizzle + PostgreSQL)

Create the complete Drizzle schema in `lib/db/schema.ts` with the following tables:

```typescript
// Users
users: id, name, email, emailVerified, image, hashedPassword, 
       credits (default: 3), plan (free|pro), planExpiresAt,
       createdAt, updatedAt

// Better Auth required tables
sessions: id, userId, token, expiresAt, ipAddress, userAgent, createdAt
accounts: id, userId, accountId, providerId, accessToken, refreshToken, 
          expiresAt, createdAt
verifications: id, identifier, value, expiresAt, createdAt

// Resume
resumes: id, userId, title, slug, templateId, content (jsonb), 
         atsScore, isPublic, createdAt, updatedAt

// Resume Templates  
resumeTemplates: id, name, thumbnail, isPremium, createdAt

// Job Applications
jobApplications: id, userId, company, position, logoUrl, salary, 
                 type (full-time|part-time|internship|contract|freelance),
                 status (dilamar|interview|penawaran|ditolak),
                 appliedDate, interviewDate, offerDate, notes, 
                 jobUrl, createdAt, updatedAt

// AI Usage Logs
aiUsageLogs: id, userId, featureType (resume_analyze|resume_analyze_jd|
             cover_letter|skill_gap|mock_interview), 
             creditsUsed, inputData (jsonb), outputData (jsonb),
             createdAt

// Transactions
transactions: id, userId, orderId, amount, credits, status 
              (pending|success|failed|expired),
              paymentType, midtransToken, midtransRedirectUrl,
              paidAt, createdAt

// Cover Letters
coverLetters: id, userId, resumeId, jobTitle, company, 
              content, createdAt, updatedAt
```

## 💳 Payment Flow (Midtrans)

Implement in `lib/payment/midtrans.ts` and API routes:

User clicks "Beli Credit"
POST /api/payment/create
→ Create transaction record (pending)
→ Call Midtrans Snap API
→ Return snap_token to client
Client opens Midtrans Snap popup
User completes payment
Midtrans calls POST /api/payment/webhook
→ Verify signature
→ Update transaction status
→ Add credits to user (or activate Pro plan)
→ Send confirmation email via Resend

Credit packages:

## ⚠️ Important Rules

- Always use **Server Components by default**, add `"use client"` only when needed (useState, useEffect, event handlers, browser APIs)
- All **API keys must stay server-side only** — never expose to client
- All **AI API calls go through `/api/*` routes** — never call Gemini directly from client
- Use **Zod for all input validation** in API routes
- Use **Server Actions** for simple form mutations where appropriate
- All database queries go through **`lib/db/`** only — never import drizzle client directly in components
- Handle **loading, error, and empty states** for all async operations
- Use **TypeScript strict mode** throughout
- Add **proper HTTP status codes** for all API responses
- **Verify Midtrans webhook signature** before processing payment
